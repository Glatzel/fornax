# Procedural Book Figure Generation

This archived plan documents the completed Procedural Book Figure Generation work.

Branch `task/book-02-figures`, worktree `.worktrees/book-02-figures`.
PR title example: `docs: add procedural figure tooling for book`. Put `BOOK-02` in the PR body and remove its `TODO.md` item in the same PR.
Requires `book-01-bootstrap` merged. Do not run in parallel with `book-03-build` (both touch `pixi.toml` and `pixi.lock`).

## Goal

Figures in `book/` are generated by scripts, not drawn by hand, using a tool declared in `pixi.toml`. The output is deterministic-as-far-as-possible pure-vector SVG that stays ignored by Git; its size is not a concern.

## Context a fresh reader needs

- Read `book/AGENTS.md` first. Its hard rule applies: no binary files and SVG with no embedded raster. Generated SVG stays ignored by Git with no size limit.
- The maintainer prefers a procedural way to produce figures, and wants gnuplot if it can do the job, otherwise a better tool.
- Tool choice made by the planner, with the reason: **Python + matplotlib**.
  - gnuplot: the conda-forge listing found while planning shows linux-64, linux-aarch64, osx-64 and osx-arm64 builds and no win-64 build, and the repo supports Windows (`scripts/setup.ps1`). A pixi dependency would fail on Windows unless scoped away. Re-check the current listing; if a win-64 build exists now, gnuplot becomes a viable alternative and the maintainer decides.
  - matplotlib: on conda-forge for all platforms, Python is already part of the repo (`fornax-py`, `ruff.toml`), handles grids, curves, annotations and math labels, and writes SVG.
  - Considered and not chosen: Rust `plotters` (adds Rust dependencies and lockfile churn to a workspace that already runs `cargo test --workspace`), Typst with CeTZ (second typesetting toolchain, package downloads at build time).

## Scope

In:

- a `book` pixi feature and environment holding the figure tooling
- `book/figures/` generator scripts, a shared helper, conventions README
- two sample figures that prove the pipeline
- pixi task to regenerate all figures

Out:

- chapter content, PDF or HTML build (`book-03-build`)
- CI regeneration or drift checks (see notes)
- any raster output

```text
  l02_level_normalization.py   sample: v = (d - b) / (w - b), clipped to [0, 1]
book/src/figures/<chapter>/<name>.svg    ignored output, regenerated locally
```

## Decisions and notes

- On 2026-11-03, `pixi search -c conda-forge gnuplot --platform win-64` found
  no package, so gnuplot remains unavailable on a declared repository
  platform. The `book` environment resolves Python 3.13.18 and
  `matplotlib-base` 3.11.2 on every declared platform. The base package
  provides the matplotlib API without an unused Qt GUI stack.
- On 2026-11-03, two consecutive `pixi run -e book book-figures` runs produced
  byte-identical SVGs on this Linux machine.
- Byte-identical output across operating systems is not promised: layout depends on font metrics. Regenerate on one machine, inspect the files there, and do not add a CI drift check.
- Figures from real Fornax data (for example comparison results) may be generated by later chapter tasks; they read data from existing project outputs and never commit sample images.
- SVG size is no longer a design constraint; keep the generator and rendering quality as the deciding factors.
