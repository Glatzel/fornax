# compare-demosaic

Compares Fornax demosaic implementations with their reference implementations
at the demosaic stage.

The current comparison uses a deterministic 512x512 synthetic Bayer mosaic
generated by `fornax-devtool` with seed `12345`. Values are quantized to 16-bit
codes and passed unchanged to every implementation:

- Fornax receives the codes as normalized `f32` samples.
- LibRaw receives the original `u16` samples.
- darktable receives normalized `f32` samples and its output is quantized back
  to 16-bit codes.

LibRaw headers and the `libraw_r` library come from the repository-managed
`libraw-dev 0.22.3` Pixi package. The comparison crate does not compile LibRaw
from source.

LibRaw's decoding, black subtraction, white balance, color conversion, and tone
mapping stages are bypassed. The adapter injects the mosaic into LibRaw's
working image and invokes only the selected interpolation routine.

The darktable reference compiles the unmodified PPG, RCD, VNG, AMaZE, and
LMMSE sources from release 5.6.2 through small adapters. The repository setup
scripts use `gh api` to materialize only the required files.

Metrics cover the three output channels. Each case declares whether its
implementation-specific border is excluded to account for reference boundary
strategy differences. MAE and maximum error are 16-bit codes, PSNR uses a peak
value of 65535 and is reported in dB, and changed values are percentages. The
table uses `f32`; tests repeat every case with both `f32` and `f64`.

Run the comparison from the repository root:

```bash
source scripts/setup.sh
pixi run -e dev compare-demosaic
```

On Windows, run `./scripts/setup.ps1` before `pixi run -e dev compare-demosaic`.

The command writes `results/canonical.json`; it does not edit this README. A
Codex agent reads that JSON, updates the per-algorithm tables, and writes an
evidence-based note after any table containing `⚠️` results.

The committed JSON and tables are Linux-canonical. Cross-platform tests still
validate the declared tolerances, but documentation freshness is checked on
Linux because compiler and math-library rounding can vary by platform.

Legend:

- `✅`: every compared sample is bit-identical.
- `🟢`: Fornax rounds to nearest while LibRaw truncates, so differences are one code upward.
- `⚠️`: every sample is within the case's declared maximum error.
- `❌`: at least one compared sample exceeds that tolerance.

## Adding an algorithm

1. Add a reference runner to `cpp/algos/<library>_<algorithm>.{c,cpp}`, or
   adapt a pinned external source without copying it into the comparison crate.
2. Add its reference backend and ID to the `switch` in `cpp/shim.cpp`.
3. Add `src/cases/<name>.rs` with a `CASE` and its Fornax runner.
4. Register the case in `src/cases/mod.rs`.
5. Run `pixi run -e dev compare-demosaic` to update the canonical JSON result.
6. Have the Codex agent update the README tables and warning notes from JSON.
7. Commit both the JSON result and README.

Reference routines and headers come from the Pixi-managed `libraw-dev` package;
the comparison crate does not compile LibRaw from the external checkout.
darktable reference source is fetched from its pinned release with `gh api`.
