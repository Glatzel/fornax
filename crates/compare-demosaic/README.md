# compare-demosaic

Compares Fornax demosaic implementations with LibRaw and darktable at the
demosaic stage.

The canonical comparison uses the full active area of
`external/raw-images/images/colorchart-eos-7d.cr2`. The image is decoded using
its `GBRG` CFA metadata, normalized using its black and white levels, and
passed unchanged as 16-bit codes to every implementation. White balance and
the default output crop are not applied.

Comparison tests do not read real images. They run every algorithm in parallel
through `rstest` against one shared 512x512 mosaic generated by
`fornax-devtool::synthetic_mono_image`.

```bash
source scripts/setup.sh
pixi run compare-demosaic
```

Setup installs the Rust environment, initializes `external/raw-images`, and
materializes the darktable reference sources. The comparison command writes:

- `results/canonical.json` for complete manual analysis, including every
  diagnostic metric.
- `results/summary.json` for concise agent-assisted README generation.

The command shows a stderr progress bar for each algorithm/reference case and
does not modify this README.

## Evaluation

For robust comparisons, verdicts require:

- MAE at most 2 codes.
- P99 absolute error at most 64 codes.
- At most 0.1% of channel samples above 1024 codes.

MAE, RMSE, PSNR, P95/P99/P99.9, high-error percentages, per-channel MAE,
luminance/chroma RMSE, changed percentage, and maximum error are stored in
`canonical.json`. Maximum error is diagnostic rather than the sole pass/fail
rule.

Exact and rounding-only cases retain their stricter semantics. Fornax clamps
reconstructed RGB to `[0, 1]` before 16-bit quantization in comparison cases.
